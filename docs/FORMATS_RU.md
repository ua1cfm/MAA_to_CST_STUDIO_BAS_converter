# Технический справочник: MMANA `.maa` и Fairbeam `.design.json`

[Основной README](../README_RU.md) · [English](FORMATS_EN.md)

Этот документ описывает **реально реализованный разбор и экспорт в v0.3.1**, а не всю спецификацию MMANA-GAL или всех версий Fairbeam. Если структура отличается в другом релизе программ, требуется отдельная проверка.

## MMANA `.maa`: структура и единицы

Это текстовый формат модели антенны. Присланные образцы содержат русские названия секций в кодировке Windows-1251; программа также пробует UTF-8 с BOM и Latin-1. **Координаты и радиусы** проводников задаются в **метрах**, рабочая частота — в **МГц**.

Упрощённый фрагмент (английские названия секций приведены для удобства):

```text
Example antenna
*
145.0
* Wires *
2, 1, 1, 0, 0, 0
0, 0, -0.5, 0, 0, -0.01, 0.001, -1
0, 0,  0.01, 0, 0,  0.5, 0.001, -1
*** Source ***
1, 1
w1c, 0.0, 1.0
*** Load ***
0, 1
*** Autosegm ***
400, 40, 2.0, 1
```

Это **пример полей формата**, а не готовая электрически проверенная модель. Источники и нагрузки текущий конвертер читает для диагностики, но не экспортирует.

### Заголовок проводов и стеки

Сразу после секции проводов идёт строка с полями:

`число_базовых_проводов, копии_по_горизонтали, копии_по_вертикали, шаг_по_горизонтали_м, шаг_по_вертикали_м, режим_размещения`

При подтверждённом для контрольных моделей режиме `0` конвертер создаёт центрированные копии по Y/Z. Необычные режимы расположения помечаются предупреждением: их точность относительно MMANA пока не доказана. Максимум копий, допустимый нынешним парсером, — 64.

### Запись проводника

`x1, y1, z1, x2, y2, z2, radius_m, segmentation_tag`

Первые шесть чисел задают начало и конец прямого проводника в метрах, седьмое — **радиус, не диаметр**, последнее — способ сегментации в MMANA. Положительный радиус означает обычный проводник постоянной толщины. **Отрицательный радиус может ссылаться на секцию комбинированного/ступенчатого проводника**; до восстановления профиля такого элемента версия v0.3.1 отклоняет экспорт. Замена на постоянный радиус `abs(radius)` считалась бы подменой геометрии.

### Источники, нагрузки и автосегментация

Источники обычно ссылаются на электрические импульсы: `W13B`, `W13C`, `W13E` (начало, центр, конец согласно правилам сегментации MMANA). Поля источника могут включать фазу в градусах и относительную амплитуду. Нагрузки могут представлять R, L, C, добротность Q и сложные комбинации. Их нужно интерпретировать по правилам конкретного варианта MMANA; они **не становятся** портами или элементами `resistors` в v0.3.1.

Автосегментация, параметры грунта и ступенчатые профили не могут быть достоверно заменены одним простым геометрическим атрибутом в экспортируемом файле.

## Fairbeam `.design.json`: структура

Конвертер записывает поле `"schema": "fairbeam.design/1"`. Сокращённый пример:

```json
{
  "schema": "fairbeam.design/1",
  "model": { "id": "maa_example", "name": "Example antenna" },
  "params": [],
  "simulation": { "f_min": 0.13775, "f_max": 0.15225,
                  "boundaries": "MUR", "end_criteria_db": -40 },
  "materials": [{ "name": "copper", "kind": "metal" }],
  "parts": [{ "name": "antenna", "material": "copper",
    "primitives": [
      { "kind": "wire", "points": [[0,0,-500],[0,0,-10]], "radius": 1 },
      { "kind": "wire", "points": [[0,0,10],[0,0,500]], "radius": 1 }
    ]
  }],
  "ports": [],
  "resistors": [],
  "mesh": { "mode": "auto", "cells_per_wavelength": 20 },
  "far_field": { "enabled": true, "frequencies": [0.145] }
}
```

### Значение основных полей

| Поле | Назначение | Единицы/примечание |
|---|---|---|
| `schema` | Идентификатор схемы | `fairbeam.design/1` |
| `model.id`, `model.name` | ID и название модели | ID образуется из относительного пути MAA |
| `params` | Параметры пользователя | В v0.3.1 пусто |
| `simulation.f_min/f_max` | Границы анализа | **ГГц** |
| `simulation.boundaries` | Граничные условия | Значение `MUR`, проверять применимость |
| `simulation.end_criteria_db` | Порог завершения | Значение `-40` |
| `materials` | Материалы | `copper`, `kind: metal` |
| `parts[].primitives[]` | Геометрические элементы | `kind: wire` |
| `points` | Две координаты XYZ | **мм** |
| `radius` | Радиус проводника | **мм**, не диаметр |
| `ports` | Источники питания | Пустой список `[]` |
| `resistors` | Дискретные элементы | Пустой список `[]` |
| `mesh` | Настройки сетки Fairbeam | `auto`, 20 ячеек/длину волны — не сегментация MMANA |
| `far_field.frequencies` | Частоты полевого анализа | **ГГц**, частота MMANA |

По умолчанию диапазон равен **±5%** от исходной частоты; его можно изменить в GUI или `--sweep-percent`. Пересчёт единиц: **1 м = 1000 мм**, **1 МГц = 0,001 ГГц**.

## Что нельзя путать

- Валидный синтаксис JSON **не означает**, что установленный Fairbeam его откроет, сетка построится, питание окажется подключённым или электромагнитный результат будет верным.
- `WnB/WnC/WnE` из MAA — ссылки на импульсы MMANA, **не готовые координаты портов Fairbeam**.
- Запись нагрузки в MAA не равна полю `resistors` без правильной электрической реконструкции.
- `reports/*.txt` — отчёты человека, не проекты Fairbeam; `.bas` — макрос CST, не JSON.
- При неподдерживаемой геометрии программа намеренно не создаёт заведомо неправильную модель.

## Как проверять результат

1. Прочитать `reports/<имя>.txt`, проверить предупреждения.
2. Сравнить координаты и радиусы с исходным MMANA после перевода в мм, проверить расстановку стеков.
3. Открыть `.design.json` в конкретной версии Fairbeam, убедиться в отсутствии ошибки схемы.
4. Вручную назначить электрическое питание, нагрузки, материалы, землю и параметры расчёта, проверить отсутствие коротких замыканий.
5. Провести проверку сходимости сетки и частотного sweep до использования S11, резонанса, ДН и E/H как инженерного результата.
6. При ошибке приложить исходный MAA, JSON, TXT-отчёт и точный текст сообщения Fairbeam.
